# Subako ワークショップ：アイデアを、動くAIアプリにする

**ゴール：自分たちが考えた体験をアプリで動かし、18:10までに60秒のデモ動画を提出する。**

全員でTODOを作った後、EC・マップのどちらかを自分の業界や興味に合わせて育てます。まず16:30までに一度動かし、その後に工夫を足しましょう。データ・指示・用意されたツールの組み合わせだけでも作品になります。独自のUI・関数・MCPの追加も自由です。

> 主催者向け：この1ファイルが教材の設計・記入用ドラフトです。教材は通常のVite + React 19 + TypeScriptアプリとして新しく作り、SubakoのSDKはハンズオンでインストールします。以下の教材固有の部品・ファイル配置・接続準備スクリプト・データ生成Webは実装予定の仕様です。SDK自体はnpmで公開されていますが、この教材を現在のリポジトリで実行できる状態ではありません。末尾の準備チェックを完了し、リンクと実際の手順を確定してから配布してください。

## 1. 開始前に普通のReactアプリを開く

事前に、PC・ブラウザー・GitHubアカウントを用意してください。動画提出はチーム代表者のGoogleアカウントを使います。開催前にCodespacesの作成と起動を一度済ませ、停止しておきましょう。

1. 教材テンプレートから、自分のGitHubアカウントにリポジトリを作り、Codespacesを開く。
2. `.env.local.example` を `.env.local` にコピーし、配布された参加者用APIキーを入れる。
3. ターミナルで次のコマンドを実行し、Portsから5173を新しいタブで開く。

```bash
npm install
npm run dev
```

`.env.local` の設定例。`VITE_` の値はフロントエンドに渡す設定として使います。

```dotenv
VITE_SUBAKO_API_KEY=ここに参加者用APIキーを貼る
```

この時点ではSubakoのSDKはまだインストールしていません。TODO・EC・マップの画面と、データ取得・画面操作の関数がある普通のReactアプリです。画面の切替メニューから各アプリを開けます。

- [ ] TODOを画面のボタンで追加・完了できた。
- [ ] ECとマップを開けた。
- [ ] 提出フォームを開けた。代表者がファイルを添付できることも事前に確認した。

起動できない場合は、この時点で運営に相談してください。

## 2. SDKをインストールし、TODOを会話で操作する（15:15–15:45）

**完成形：「準備を3件追加して」でTODOが増え、「これは完了した」で画面が更新される。**

1. **最初の5分：** 講師の完成デモを見て、別ターミナルでSDKとチャットUIをインストールする。
2. **次の5分：** 指示を編集して配布スクリプトでpublishし、APIキーを使うクライアントとProviderを追加する。
3. **次の10分：** `SubakoChat` と読む・追加するツールを組み込み、最初の入力を試す。
4. **次の5分：** 完了ツールを追加し、会話と手動操作の両方で状態が変わることを確認する。
5. **最後の5分：** 指示を変更し、再publishと新しい会話で試し直す。

インストールするパッケージ（2026-09-13にnpmの公開を確認した版。開催用の版は運営が通し確認して固定します）：

```bash
npm install @subako-ai/sdk@0.1.0 @subako-ai/react@0.1.0 @subako-ai/assistant-ui@0.1.0 @assistant-ui/react@0.15.19 @assistant-ui/react-markdown@0.14.15
```

`agents/todo/prompt.md` に入れる指示の例：

```text
あなたは、このTODOアプリを操作するアシスタントです。日本語で短く答えてください。
現在のTODOは一覧取得ツールで確認し、取得したIDを使って操作してください。
依頼された追加・完了はツールで実行し、成功した後に報告してください。
```

別ターミナルで、用意されたスクリプトを実行します。

```bash
npm run agent:publish -- todo
```

このスクリプトがagentの作成・publish、ブラウザーのOriginの許可、新規sessionの作成を行い、`.env.local` の `VITE_TODO_SESSION_ID` を更新します。完了後に開発サーバーを再起動し、ブラウザーを再読み込みしてください。接続準備はCodespacesのターミナルで完結します。

`src/subako.ts` を作り、APIキーを使うクライアントを初期化します。

```ts
import { SubakoClient } from "@subako-ai/sdk";

export const subako = new SubakoClient({
  apiKey: import.meta.env.VITE_SUBAKO_API_KEY,
});
```

`src/App.tsx` の既存の画面切替部分を `SubakoProvider` で囲みます。`client` には `subako.sessions` を渡します。

```tsx
import { SubakoProvider } from "@subako-ai/react";
import { subako } from "./subako";

// Appのreturn内。既存の画面切替部分をそのまま中に置く。
<SubakoProvider client={subako.sessions}>
  {/* 既存のTODO・EC・マップの画面切替 */}
</SubakoProvider>
```

`src/todo/Workshop.tsx` の組み込み例。`useTodoApp` と `TodoView` は、SDK導入前から動く配布済みのアプリ部品です。`sessionId` は画面切替側から `import.meta.env.VITE_TODO_SESSION_ID` を渡します。IDがまだないアプリは手動操作用の画面を表示するよう、切替部分に用意しておきます。

```tsx
import { SubakoChat } from "@subako-ai/assistant-ui";
import { useSession, useTool, useToolClient } from "@subako-ai/react";
import { TodoView, useTodoApp } from "./features/todo";

export function Workshop({ sessionId }: { sessionId: string }) {
  const app = useTodoApp();
  const session = useSession(sessionId);
  const client = useToolClient(session, "todo");

  useTool(client, "list_todos", app.tools.listTodos);
  useTool(client, "add_todo", app.tools.addTodo);
  // 追加が動いたら、この行も登録する：
  // useTool(client, "set_todo_done", app.tools.setTodoDone);

  return (
    <main className="workshop-layout">
      <TodoView app={app} />
      <SubakoChat session={session} />
    </main>
  );
}
```

講師と `app.tools.addTodo` の `description`・`parameters`・`execute` を開いて確認します。`execute` は、ボタンと同じアプリの操作関数を呼びます。

- [ ] 「サンプルを起動する、テーマを決める、発表を練習する、を追加して」で3件増えた。
- [ ] 「サンプルを起動する、は完了した」で該当するTODOが完了になった。
- [ ] 画面で別のTODOを完了にしてから「残りを教えて」と聞き、手動操作も反映された。

## 3. 見せたい体験を決め、データを用意する（15:45–16:10）

15:45にコーヒーを題材にした2つの作品例を各60秒程度で紹介します。最初の10分の残りで下を仮決めしてください。このメモをデータ生成と最後の提出説明に使います。

### 作品例：好きなコーヒーを「家で楽しむ」「街で楽しむ」

| | EC：好みからコーヒー豆をバンドル購入 | マップ：コーヒー屋巡りのルートを作る |
| --- | --- | --- |
| 最初の相談 | 「酸味控えめが好き。3,000円以内で3種類の飲み比べセットを作って」 | 「駅から90分で2軒回りたい。雰囲気の違うお店を組み合わせて」 |
| AIの役割 | 好みと予算を聞き、豆の特徴を読んで組み合わせを提案する | 希望と移動・滞在時間を踏まえ、お店と回る順番を提案する |
| 画面で起きること | 豆のカードと選んだ理由、袋数・合計が表示される。セットをカートに入れ、人が購入を確定するデモへ進む | 地図のピン・徒歩経路・訪問順・所要時間の目安が表示される |
| もう一往復で見せる工夫 | 「2つは好みに合わせて、1つは普段選ばないものにして」で一部を入れ替える | 人が1軒を固定して「ここは残して、60分に短くして」でルートを組み直す |
| 使うデータ | 豆8〜12件。味の説明・焙煎度・酸味などの属性、内容量・デモ価格・在庫 | 一つの地域の店舗5〜8件。確認済み座標・店の特徴・滞在時間目安、出発点と店舗間の徒歩経路・時間 |

この2つは選べる完成例です。コーヒーのまま別の体験に育てても、自分の業界や趣味のデータへ置き換えても構いません。ECの「組み合わせて選ぶ」はギフトや広告メニューへ、マップの「条件を守って回る」は販売店巡りや会場下見へ広げられます。完成例のコードは希望者が参照できるようにし、教材の開始状態はSDK未導入のReactアプリにそろえます。

15:55から、画面の切替メニューでECまたはマップを開きます。SDKは同じReactアプリへ導入済みなので、ここで再インストールする作業はありません。

次に、主催者の**データ生成Web**をブラウザーで開きます。Chat Exampleをベースに主催者が提供する別のWebアプリです。上のメモを渡して8〜12件の下書きを作り、プレビューで確認してJSONをダウンロードしてください。EC・マップの「データを変更」から読み込みます。

- 題材・利用者・判断項目を渡すと、アプリに合う形式で生成されます。参加者による生成用エージェントの実装やpublishは不要です。
- デモ用の架空データで始められます。実在製品の性能や料金と区別できる名前・説明にしましょう。
- マップは配布済みの座標付きスポットを使い、属性や説明を変えるところから始めます。自分の地域は座標を確認できたデータを使います。
- 画像は任意です。標準のアイコンとカードでデモできます。
- **16:10で一度区切ります。** 間に合わなければ3〜5件に減らすか、配布済みのコーヒー豆カタログ／コーヒー屋マップを使います。

## 4. まず一度動かし、工夫を足す（16:10–17:55）

選んだ画面に、TODOと同じ方法でエージェントを組み込みます。以下はECの例です。マップはパスの `ec` を `map` に置き換えます。

| ファイル | 変えられること |

| `src/ec/Workshop.tsx` | `useTool` の登録、アプリとチャットの配置 |
| `agents/ec/prompt.md` | 誰を助けるか、質問・判断・操作の方針 |
| `agents/ec/mcp.json` | 外部情報を使うMCP設定（初期値は `[]`） |

TODOと同じ構成で、`app.tools` に取得・画面操作の関数とツール定義を用意します。`Workshop.tsx` で同じsessionをチャットとツールへ渡し、`SubakoChat` を配置して、選んだアプリの4行を追加してください。

```tsx
// ECを選んだ場合
useTool(client, "search_products", app.tools.searchProducts);
useTool(client, "show_products", app.tools.showProducts);
useTool(client, "get_selection", app.tools.getSelection);
useTool(client, "set_selection", app.tools.setSelection);
```

```tsx
// マップを選んだ場合
useTool(client, "search_places", app.tools.searchPlaces);
useTool(client, "highlight_places", app.tools.highlightPlaces);
useTool(client, "get_selection", app.tools.getSelection);
useTool(client, "set_selection", app.tools.setSelection);
```

エージェントの指示に、先ほど決めた利用者と判断方針を加えます。共通の指示は「ツールでデータと現在の選択を読み、条件に合う候補を画面に示す。選択を頼まれたら更新する。IDや値は取得したデータを使い、成功した後に理由を説明する」です。指示を保存したら `npm run agent:publish -- ec` を実行します。マップは `map` を指定します。スクリプトはそれぞれ `VITE_EC_SESSION_ID` / `VITE_MAP_SESSION_ID` を更新するので、開発サーバーを再起動し、ブラウザーを再読み込みします。画面切替側から対応するIDを `Workshop` に渡してください。

**16:30までのチェック：**「この条件に合う候補を2つ見せて」→「こちらを選択リストに入れて」で、画面が変わるところを確認します。

- [ ] 自分のデータを検索し、候補がカードまたは地図に表示された。
- [ ] 指定した候補が選択リストに入った。
- [ ] この流れを30秒程度で見せられる。ここで最初の完成！

## 5. 60秒の動画を提出する（17:55–18:10）

**17:55になったら録画へ切り替え、18:10までにチーム代表者がフォームから送信します。**

動画は画面録画のままでOKです。編集・スライド・BGMは不要で、無音でも説明文で補えます。MP4 / MOVを提出できる運用にします。目安は「最初の10秒：誰の何を助けるか → 次の40秒：入力から画面が変わるまで → 最後の10秒：工夫した点」です。

| 提出項目 | 記入メモ |
| --- | --- |
| チーム名・メンバー・作品名 | |
| 誰の、どんな困りごとを解決するか（100字程度） | |
| デモ動画（60秒以内・1本） | |
| 工夫したところ（200字程度） | |
| 実装して動く範囲／今後の構想（各一文）、使ったSubakoの機能 | |
| リポジトリ・アプリURL（任意） | |

- [ ] デモを一度通して確認し、録画した。
- [ ] 動画と説明を添付して送信し、提出完了を確認した。

録画に失敗した場合は、同じ締切までに操作前後のスクリーンショットと説明を代替提出できます。アプリURLの公開は任意です。動画は運営のPCから連続上映し、1チーム60秒まで。追加の口頭発表・質疑は設けず、続きは懇親会で話しましょう。

審査では「対象ユーザーに役立つか」「狙った体験が動くか」「判断や操作に工夫があるか」を見ます。動画編集のうまさやMCP・機能の数は評価対象にしません。

コーヒーECの完成例は、3,000円以内で3種類を選べるデモ価格を用意し、合計・数量・在庫をアプリの関数で検証します。購入は人がボタンで確定するデモとし、実決済の接続は準備範囲に含めません。

コーヒー屋巡りの完成例は、出発点と少数の店舗を対象に、徒歩経路と所要時間を事前に取得・確認して持たせる構成から始めます。候補ルートの取得と地図への反映を関数として用意し、移動時間と滞在時間を合計して時間内に収まるか確認します。直線で結んだ線を徒歩経路として表示せず、経路データの配信元・利用条件・表示も実装時に確認します。営業時間や混雑を扱う場合は、情報の時点と未確認の項目が分かるようにします。

画像生成、独自地域の住所検索、任意の場所を対象としたリアルタイム経路探索は余裕があれば追加するものとします。参加者の最初の完成条件は、引き続き候補の表示と選択リストの更新です。

### 実装上の前提：接続準備はターミナル、会話とツールはReact

確認した現行のSubako APIは、`/v1/sessions/{session_id}` 配下に対してagentの `allowed_origins` を使ってCORSを許可します。agentの作成・publishや `/v1/sessions` への新規作成はブラウザーから呼べません。このため、配布するNodeスクリプトで準備し、既存sessionへの会話・ツール操作をフロントのAPIキーで行います。参加者が起動する常駐プロセスはViteだけです。

スクリプトはCodespacesの転送Originまたはlocalhostを登録し、参加者・アプリごとのagent IDを再利用します。session IDは `.env.local` のアプリ別変数に書き、他の設定を保持します。フロント用のsession tokenファイルや発行用HTTPサーバーは準備項目から外します。ブラウザーでのsession作成まで求める場合は、Subako API側のCORS対応を別途設計する必要があります。

`SubakoProvider` に `SubakoClient.sessions` を渡せることは、ローカルSDKを使った型チェックで確認しました。公開パッケージの型定義も確認済みです。実際のクラウド接続は開催版で通し確認します。
